# 그린스마트 Cloud 공개 안내

> 문서 기준일: 2026-10-20 · 용도: Cloud의 역할, 공개 배포 정보와 설치·업데이트 지원 조건 안내

Cloud는 그린스마트 플랫폼의 **메인서버**입니다. 회사 운영 직원이 고객·농장·Edge를 관리하고, 기상청·농약 등 외부 자료를 이용 조건에 맞게 수집·검증·가공하여 허용된 Edge에 전달합니다. 플랫폼 전체의 현장 판단은 각 Edge가 담당하며, Cloud가 PLC·IoT로 직접 우회 제어하는 구조로 계획하지 않습니다.

[플랫폼 전체 안내](https://github.com/greenity-corp/greensmart_release) · [Cloud 릴리즈 목록](https://github.com/greenity-corp/green_smart-cloud-releases/releases) · [Edge](https://github.com/greenity-corp/green_smart-edge-releases) · [Controller](https://github.com/greenity-corp/green_smart-controller-releases)

## 1. 이 저장소와 현재 상태

이 저장소는 승인된 **Cloud 공개 안내·변경 내역·지원 조합·Cloud 전용 산출물**을 게시하는 채널입니다. 제품 소스와 상세 계획은 접근을 제한한 `greenity-corp/green_smart`에서 관리합니다. 개발 저장소나 고객별 자료 보관소로 사용하지 않습니다.

2026-10-20 12:54 KST GitHub Releases API 확인 결과, 이 채널의 반환 목록은 비어 있었습니다. 이는 해당 시각의 게시 현황이며 현장 운영·설치 상태의 조사 결과가 아닙니다. 현재 이 안내에는 검증된 공개 설치 파일·설치 명령·지원 버전 조합을 제시하지 않습니다. 최신 게시 여부는 위 릴리즈 목록을 확인하세요.

새 기준 문서에 정리한 기능·페이지는 구현과 검사를 위한 계획입니다. 새 직원 앱·개발 현황 연계·릴리즈 관리 화면·고객 현장 버전 지원이 이미 제공된다는 뜻은 아닙니다. 다음 단계는 UI 템플릿/컴포넌트 레퍼런스 비교·선정과 최소 구현·검사이며, 실제 공개 출고는 별도 검토·승인 후 진행합니다.

## 2. 주요 업무와 다른 앱의 경계

| 업무 방향 | Cloud가 제공할 내용 | 구분할 책임 |
| --- | --- | --- |
| 서비스 첫 화면 | 지원 기술·서비스 전반, 현재 제공/준비 상태와 문제·관련 업무 | 미수집·불명·미구현을 정상 또는 실제 0으로 표시하지 않음 |
| 고객·농장·Edge 관리 | 관계·등록 단계, 허용된 상태/요약 사본·지원 이력 | 중앙 등록이 Edge 현장 준비·장치 활성화 완료를 뜻하지 않음 |
| 외부 자료 처리 | 원천·상품·공간/시각·이용 조건을 확인한 수집·허용 가공·전달 | 기상 측정소와 예보 격자 등을 구분. 농장 데이터/지역 그룹 명단을 자동 공용화하지 않음 |
| 전달·관리 추적 | 대상 Edge에 대한 허용 요청·전달·수용/적용 결과의 분리 표시 | Cloud 접수/전달이 Edge 적용 완료를 뜻하지 않음. 현장 판단과 안전 조건은 Edge |
| 앱 개발·검사 현황 | Core·Cloud·Edge·Controller별 목표·진행·검사·막힘의 근거를 허용된 내부 업무에 제공 | 내부 개발 원문과 고객용 공개 안내 분리. CI 성공은 출고·현장 설치 성공이 아님 |
| 릴리즈·현장 버전 지원 | 후보/승인/게시/철회, 공개 변경과 지원 조합, 고객 현장 실제 보고·설치/실패/복원 상태 비교 | 실제 수집/확인 시각과 불명을 표시. 지원 화면이 새 원격 실행 권한을 만들지 않음 |

고객 기본 접점은 자기 농장의 Edge입니다. 이 계획만으로 고객이 Cloud 직원 콘솔에 접속하는 포털·로그인을 새로 제공한다고 선언하지 않습니다. 향후 고객에게 보여줄 정보는 자기 현장에 허용된 릴리즈·지원 안내와 공개 허용 정보로 한정합니다.

## 3. 클라이언트와 서버 산출물

| 구분 | 목적·대상 | 릴리즈에서 따로 확인할 것 |
| --- | --- | --- |
| Cloud 서버 실행부 | 메인서버의 관계·외부 자료·허용 교환·직원 업무 처리 | 실행 환경, DB/파일·이행/백업/복원 조건, Edge와 계약/버전 호환, 기동/업무 검사 |
| Cloud 직원 클라이언트 | 기존 서버에 접속하는 데스크톱·후속 모바일 앱 | 실제 제공 OS/CPU, 서버 접속/인증, Core 소비 버전, 설치·권한/종료·단절/재개 조건 |
| Core 소비 자산 | Cloud가 사용하는 공통 규격·코드·UI/템플릿 | 앱에 포함된 실제 버전과 호환 조건. 별도 Core 서버·설치 파일이 필수라고 가정하지 않음 |

클라이언트는 공통 기반 언어의 원본에서 **Windows·Linux를 먼저**, Android·iOS·macOS는 이후 개발하는 방향입니다. 모든 Windows 버전·Linux 배포판을 지원한다고 약속하지 않습니다. 구체 프레임워크·UI 라이브러리·패키징 형식·최소 OS/CPU는 선정과 대상별 검증 후 안내합니다. 클라이언트 종료는 Cloud 서버나 Edge 실행부의 종료가 아닙니다.

## 4. 릴리즈 확인·설치·업데이트 순서

1. Cloud 릴리즈 목록에서 정식/사전 배포·철회/지원 상태, 변경 영향과 알려진 제한을 확인합니다. 서버 파일과 직원 클라이언트 파일을 구분합니다.
2. 설치할 자산의 정확한 앱·버전·대상 OS/CPU·식별자와 현재 Cloud 서버/클라이언트·Edge·Controller·Core 소비 버전/계약을 지원 조합과 비교합니다.
3. 서버/DB·파일 이행, 외부 자료 작업·미완료 요청, 직원/서비스 인증과 현장 교환의 영향, 중단/복구 조건을 확인합니다. 공개 안내가 있다고 원격관리 범위나 고객의 동의가 확대되지 않습니다.
4. 승인된 릴리즈가 지정한 경로에서 해당 자산만 내려받아 자산별 체크섬·서명·신뢰 가능한 발행자/출처를 검증합니다. 아직 게시하지 않은 명령·다운로드 주소·검증 키를 임의로 만들지 않습니다.
5. 정해진 적용 순서를 따르고 서버 기동·직원 접근·허용 대상 조회·외부 처리·Edge 교환 결과를 확인합니다. 새 클라이언트는 실제 대상 OS에서 접속·권한 거절·단절/재개·종료를 따로 확인합니다.
6. 실제 설치 버전·검사 범위·남은 제한을 기록합니다. Cloud 화면에 표시된 마지막 현장 보고가 현재 설치 상태와 같다고 가정하지 않습니다.

공개 릴리즈에는 정확한 자산·공개 허용 source 식별과 Core 소비 버전, 실제 검사한 앱/계약 조합, 미지원/미검증 조건, 이행·중단·복구·설치 후 확인, 알려진 문제를 함께 안내합니다. 체크섬 일치만으로 발행자 신뢰를 대신하지 않습니다. GitHub의 자동 `Source code` 압축 파일은 이 공개 저장소의 태그 내용이며 제품 설치 파일이 아닙니다. [GitHub 공식 릴리즈 문서](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)

## 5. 실패·단절·복구 시 판단

| 상황 | 처리 원칙 |
| --- | --- |
| 외부 자료 수집·가공 실패/만료 | 실패·출처·시각·유효성을 구분. 오래된 자료를 새 자료나 실제 관측으로 바꾸지 않음. 사용 가능 여부는 Edge의 해당 업무 조건으로 판단 |
| Cloud↔Edge 단절 | 마지막 확인과 미확인을 표시. Cloud가 Controller로 우회하지 않으며 Edge의 로컬 권한·관측·DB·안전 조건에 따른 업무 지속 여부와 분리 |
| 관리 요청 결과 불명 | 기존 요청의 기록과 Edge 실제 결과부터 대조. 임의 성공 처리나 새 요청으로 반복 제출하지 않음 |
| 개발/릴리즈 정보 수집 실패 | 미확인과 수집 시각 표시. 현장 보고·직원 업무·로컬 제어를 개발 정보 수집의 상시 성공에 종속시키지 않음 |
| 설치·DB/파일 이행 실패 | 해당 배포의 중단 조건에 따라 멈추고 실제 변경 범위·기동/업무 상태 확인. 바이너리 되돌림과 데이터 복원 가능성을 따로 판단 |
| 백업 복원 | 현재 유효한 권한·연결 관계·미완료 작업을 다시 확인. 회수된 접근이 과거 백업으로 부활하지 않도록 확인 후 제한된 업무부터 검증 |

CI·가상 시험·브라우저 E2E와 실제 서버/DB 이행·설치 OS·현장 장치 시험을 구분합니다. 통과·실패·생략·미실행·미지원은 각각 표시하며, 공개 릴리즈와 운영 적용은 해당 검사·검토·승인 근거로 판단합니다.

## 6. 공개 정보·농장 격리·지원

기본 방향은 **A 농장이 A 농장 정보와 서버가 공유 허용을 확인한 공용 정보만 받는 것**입니다. Cloud에는 환경 요약·경보·관리 상태 등 요약/주요 이벤트 중심 전달을 계획하고 상세 관측의 원본은 Edge에 둡니다. 구체 항목·주기·보존과 실제 계약 전환은 후속 검증 사항입니다. 이 README는 실제 격리·전환 시험의 완료 증거가 아닙니다.

공개 채널에는 승인된 일반 안내·릴리즈 설명·허용 산출물만 게시합니다. 비공개 기준 문서 원문·내부 PR/CI 로그·직원 운영 자료·고객/농장/장치 정보·내부 주소/설정·자격정보·개인키와 검증하지 않은 파일/임의 체크섬은 게시하지 않습니다. 고객별 버전·장애·지원 이력도 이 공개 저장소의 게시 대상이 아닙니다.

지원 요청에는 공개 가능한 앱/서버/클라이언트 버전·OS·발생 시각·민감정보를 제거한 증상·확인 결과를 준비합니다. 지정된 비공개 지원 창구가 있으면 그 경로로 전달하고, 공개 이슈에 현장 로그/설정 원문을 첨부하지 않습니다. 공개 연락처·응답 시간·지원 수치는 아직 이 안내에서 정하지 않습니다.

## 7. 유지관리

새 기능은 관련 검사와 사용자 경로의 E2E 시나리오에 연결하고, 앱/계약·필요한 이전/새 버전 조합을 실제로 검사한 범위만 지원 근거로 남깁니다. 내부 개발 근거에서 고객용 설명을 별도로 검토해 공개하고, Cloud의 릴리즈/지원 정보와 이 저장소의 버전·상태·링크가 어긋나지 않도록 갱신합니다. 운영 실패·복구와 개선 효과는 다음 계획의 입력으로 기록합니다.

README 변경은 새 자산 게시·자동 업데이트·서버/현장 배포를 실행한 기록이 아닙니다. 실제 게시와 설치/운영 적용은 별도 검토·승인을 거칩니다.
